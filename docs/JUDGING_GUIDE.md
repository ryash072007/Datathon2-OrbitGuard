# Evaluator guide

For people, or an AI, reading this repository. Each bullet is a claim plus the exact file, command or artefact
that backs it. Event: IBM Z Datathon 2026, code SSF2026, theme Real-Time AI for Critical Decisions. OrbitGuard is
decision support: an operator decides, and the tool never commands a spacecraft.

Numbers come from artefacts under `artifacts/` (gitignored, regenerated by the pipeline) and each one names the
machine it was measured on. The console shows "missing" where an artefact doesn't exist. The README "Results"
section separates what was measured on LinuxONE from what was measured on a development PC.

## 1. Value and theme alignment

- **The problem is real and measured.** Only 66 of 8,293 usable ESA training events end at high risk, and 12 of 97
  teams beat "copy the latest message" in the 2019 challenge. Proof: README "The problem, with data";
  `orbitguard evaluate`.
- **Avoiding one object can endanger another, and we counted it.** On 50 frozen stress scenarios pair-only avoidance
  introduced 20 secondary hazards and OrbitGuard 0, at the same mean delta-v, with 10 of 10 correct abstentions.
  Proof: `orbitguard benchmark-planner` then the Validation tab (policy table); `docs/RESULTS.md` (LinuxONE run).
- **Detect, Decide, Respond is covered end to end.** Encounters (Act / Wait / Monitor), Manoeuvre planning and Live
  catalogue (burn screening, consequence, brief, Ask), then the audit log. Proof: the console tabs; README "What it does".
- **A human stays in the loop.** Accept / defer / reject is logged to a SHA-256 hash chain. Proof: Live catalogue
  audit panel; `orbitguard audit-verify`.

## 2. Novelty

- **All-object Pc gating with abstention.** A burn is recommended only if every close approach, old or new, stays
  below the Pc limit at 0.5x, 1x and 2x uncertainty; otherwise the tool says no safe option. Proof:
  `orbitguard/catalog/screen.py` (`recommend`), `orbitguard/physics/risk.py`.
- **AI proposes, physics verifies.** Constrained Bayesian optimisation searches between the grid's burns, and every
  pick is re-checked by the full rule. Proof: `orbitguard/optimise/`; `orbitguard optimise-burns synthetic --count 50 --budget 37 --seed 0`.
- **Measured guards on the AI's writing.** A numeric guard and a claim checker check every brief and Ask answer.
  We also tested Granite Guardian, which caught 0 of 40 subtle errors, so it ships off. The 8-of-10 held-out
  figure is the honest one. Proof: `orbitguard/brief/guard_eval.py`; `orbitguard guard-eval --n 40 --seed 0`.
- **Consequence-aware ranking.** Pc rank versus expected-harm rank (Spearman 0.78 on 20 events, 11 move 3 or more places).
  Proof: `orbitguard consequence`, `orbitguard network`; README "Results".

## 3. Technical use of IBM LinuxONE and open-source AI/ML

- **Runs on s390x, big-endian, z17.** Proof: `docs/vm_capture/platform.txt`, `bash scripts/evidence.sh`; the console
  "IBM LinuxONE platform use" card reads the live host.
- **Telum NNPA, measured.** Keras MLP through the IBM zDNN TensorFlow plugin: 1.06x at 1k rows to 2.67x at 1M rows.
  Proof: `docs/vm_capture/nnpa.txt`, `orbitguard nnpa-bench`, `artifacts/nnpa/nnpa_bench_*.json`.
- **Snap ML on zDNN.** Boosted trees scored with `tree_format="zdnn_tensors"`, CPU versus accelerator. Proof:
  `orbitguard zai-fit && orbitguard zai-eval && orbitguard zai-bench`, `artifacts/zai/snapml_bench_*.json`. The result
  names its backend; a CPU-only run says CPU.
- **Granite 3.3 2B on the box (Guardian converted the same way, evaluated).** Big-endian GGUFs in llama.cpp, no external AI API. Proof:
  `docs/vm_capture/granite.txt`, `docs/vm_runbook.md`, `scripts/convert_granite_bigendian.sh`.
- **Porting done properly.** sgp4 C extension built from source (pure Python was about 70x slower), explicit `<f8`
  byte order, spawn-safe multiprocessing, models retrained on the VM instead of copied. Proof: `scripts/bootstrap-linuxone.sh`,
  `orbitguard/catalog/`.
- **Operations and integrity.** Hardened systemd unit, s390x container, SHA-256 model fingerprints and audit chain
  (OpenSSL, which uses CPACF where present). Proof: `deploy/orbitguard.service`, `Dockerfile`, `cpacf_crypto.txt` from `scripts/evidence.sh`.

## 4. Execution and pitch

- **One command regenerates the numbers.** `bash scripts/run-linuxone-pipeline.sh` stops on the first failure and
  logs skips to `artifacts/pipeline/status.log`.
- **Tests.** 170+ tests: `.venv/bin/python -m pytest -q`.
- **The UI cannot invent a metric.** It reads artefacts and shows "missing". Proof: `frontend/src/AiEvidence.tsx`.
- **Evaluation hygiene.** Sealed test labels opened only after the model is frozen, SHA-256 recorded before and
  after; features only from messages at least 48 hours before TCA. Proof: `orbitguard/ml/data.py`, `docs/ACCURACY_REVIEW.md`.
- **Pitch.** The demo video is linked at the top of the README, and every spoken number is shown on screen.

## AI Innovation Excellence rubric

- **Right tool for the job, and honest about it.** The console's "Where the AI helps, and where it doesn't" card set
  compares each AI part with a non-AI baseline. Proof: Validation tab; `docs/evidence/`.
- **Forecasting: no significant gain.** Decision-layer loss 0.680 vs 0.694, paired 95% CI [-0.071, +0.040]. We keep
  the baseline. Proof: `orbitguard decision-eval`, `artifacts/ml/decision_evidence.json`.
- **Ranking: a small, significant gain.** Average precision 0.7005 vs 0.6651, CI [+0.004, +0.064] (LinuxONE). Proof:
  `orbitguard evaluate-triage`.
- **Search: a real gain.** Median delta-v 0.875x the grid, CI [0.826, 0.889], 30 wins, 10 ties, 0 losses; random
  search at equal budget is worse than the grid. Proof: `artifacts/optimise/evidence.json`.
- **Workload: no gain at an equal alert budget.** Triage catches 110 high-risk events vs 115 at 178 alerts. Proof:
  `orbitguard workload-eval`, `artifacts/ml/workload_evidence.json`.
- **Generative AI is constrained.** No LLM sits in the decision path; Granite narrates facts, and two guards can
  swap in a template. Proof: `orbitguard/brief/`, `artifacts/llm/guard_eval.json`.

## What we deliberately don't claim

- We don't forecast collisions. The ESA target is a later reported risk estimate, not an observed event.
- We don't claim a better point forecast than the baseline, or a workload saving at an equal alert budget.
- We don't claim "guaranteed safe". Public TLEs carry about 1 km of error and no covariance, so catalogue Pc is a
  screening indicator and the burn model ignores drag.
- We don't claim the learned burn search beats the grid on real conjunctions. The gain is measured on the synthetic
  suite; the live catalogue has one event.
- We don't claim Secure Execution or pervasive encryption. They are a design note. CPACF use is inferred from
  OpenSSL plus the recorded msa flags, with throughput measured.
- We don't call any CPU run an accelerator run. Backends are named in the artefacts.
- We don't claim "99% accurate". Most events are low risk, so accuracy alone says little; read recall, missed
  alerts and false alarms together.
- The public ESA test set was reused across versions, so later checks are retrospective, not blind. Granite 2B
  sometimes picks wrong tool arguments in Ask, and then the template answer is used.

## Reproduce in 3 commands

```bash
bash scripts/bootstrap-linuxone.sh                       # on the s390x VM (laptop: pip install -e '.[dev]')
.venv/bin/orbitguard fetch-data && .venv/bin/orbitguard prepare-data
bash scripts/run-linuxone-pipeline.sh                    # then: orbitguard serve --port 8080
```

Optional stages run if Snap ML imports (`zai-*`) and `GUARDIAN_MODEL_PATH` is set (`guard-eval`). See
[vm_runbook.md](vm_runbook.md). Restart the service after retraining so its cached model matches the evaluated
files; the API rejects forecast evidence whose fingerprint no longer matches.

## Notes on the earlier accuracy work

- The ESA scoring is reproduced (loss 0.69396 on 2,167 held-out events). Details and fingerprints: [ACCURACY_REVIEW.md](ACCURACY_REVIEW.md).
  The original deployment report is [RESULTS.md](RESULTS.md); it predates the combined build, so do not conflate it with a new run.
- The forecast-floor fix repairs lost numerical information. The shrinkage method and the separate triage
  classifier are experimental, with intervals that cross zero or modest effects. The latest-risk baseline stays default.
- Serialized models must be loaded in a matching environment. Retrain on the target machine rather than copying.
